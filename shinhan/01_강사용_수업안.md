**활동 4 추출 채점** (`02_extract.py`, gold 27건 × 23필드)
- 개선 전 전체 **77.6%**. 100%: 쿠폰율·CUSIP·원금·자동콜·발행사 콜·디지털 / 93%: 배리어·추정가치 / **낮은 3개: 가격결정일 19%, 만기일 22%, 발행일 26%**, 그다음 상품군 30%, 기초자산 33%.
- 날짜가 낮은 이유: 정규화 텍스트의 날짜가 `April 17,2026 ,`처럼 쉼표 뒤 공백이 없다. 규칙 `DATE`는 `,\s+`(공백 필수)를 요구하고 `_date()`도 `"%B %d, %Y"`로만 읽는다. 정답 27건 중 7건은 SEC 원문에서 만든 텍스트라 날짜가 정상이어서 0%가 아니라 19~26%가 나온다.
- **모범 개선**(두 줄): `DATE`의 `,\s+` → `,\s*`, `_date()`에서 `re.sub(r",\s*", ", ", …)`로 쉼표 뒤 공백을 맞춘다 → 전체 **93.2%**, 날짜 89~100%, 그리고 상품명이 `due <날짜>`로 잡히면서 **상품군 30% → 93%, 기초자산 33% → 85%**. "규칙 한 줄이 여러 필드에 번진다"가 핵심 메시지.
- 개선 후 낮은 필드(다른 조 배정용): 하방 유형 78%, 쿠폰 배리어 81%, 상승 참여율 85%.
- 생각해 보기 답: `my_products`는 1,890행(공시 1건 = 1행, CUSIP 1,268종, 원금 추출 960행) — 예비·최종이 중복되고 다상품 공시는 한 행으로 뭉친다. `products`의 9월 제출 상품은 **907개(공시 900건)**. 문서 수 ≠ 상품 수.

### 2일차

**활동 6 전체 채점표** (`05_eval_all.py`, 일반 질문 20개, hit@5)

| 질문 형태 | 키워드 | 벡터 | 하이브리드 |
|---|---|---|---|
| 영어 원래 질문 | 55% | 50% | **80%** |
| 바꿔 말한 영어 | 20% | 25% | 30% |
| 한국어 그대로 | 0% | 25% | 25% |
| 한국어 → 영어 검색어 | 60% | 65% | **70%** |

- 메시지: 키워드와 벡터는 **서로 다른 질문**을 맞힌다 → 합치면 영어 원래 질문이 55%·50% → 80%. 한국어는 벡터만 조금 찾는다(25%). 가장 큰 개선은 **질문을 공시 용어로 바꾸는 단계**(한국어 25% → 70%).
- 응답 시간(서울 → Japan East): 키워드 0.16초, 벡터 0.15초, 하이브리드 0.36초. 같은 실행을 반복해도 같은 숫자가 나온다(키워드 동점은 chunk_id 순).
- 실험 C (`--weights`): 키워드:벡터 1:1이 가장 좋다. 1:2는 영어 70%, 2:1은 65% → "한쪽에 더 기대면 오히려 떨어진다".
- 실험 A (`01_load.py --table chunks_a --header` → `04_embed.py --table chunks_a` → `05_eval_all.py --table chunks_a`, 약 17분, 임베딩 약 $0.22):

  | 질문 형태 | 벡터 전 → 후 | 하이브리드 전 → 후 |
  |---|---|---|
  | 영어 원래 질문 | 50% → **70%** | 80% → 75% |
  | 바꿔 말한 영어 | 25% → **40%** | 30% → 35% |
  | 한국어 그대로 | 25% → **5%** | 25% → 5% |
  | 한국어 → 영어 검색어 | 65% → 65% | 70% → 70% |

  → 머리글(상품명·CUSIP·예비/최종)은 **벡터 검색을 크게 올리지만** 한국어 질문은 오히려 떨어뜨리고, 하이브리드 전체는 거의 그대로다. "한 지표만 보고 개선이라 부르지 않는다"를 짚는 사례. 실험 표가 하나 늘 때마다 DB가 약 850MB씩 늘어난다(무료 32GB 안).
- 실험 B (청크 600자, Windows 리허설에서 Claude가 수행): 청크 97,196개(2배), 토큰은 오히려 4% 적은 1,063만(비용은 글자 수에 비례), 적재 70초 + 벡터화 7.7분 + **HNSW 색인 13.2분**, DB 1.8→3.0GB.

  | 질문 형태 | 키워드 | 벡터 | 하이브리드 |
  |---|---|---|---|
  | 영어 원래 질문 | 55 → 45% | 50 → 55% | 80 → 70% |
  | 바꿔 말한 영어 | 20 → 10% | 25 → 20% | 30 → 25% |
  | 한국어 그대로 | 0 → 0% | 25 → 20% | 25 → 20% |
  | 한국어 → 영어 검색어 | 60 → 45% | 65 → 55% | 70 → 60% |

  → 12칸 중 11칸이 같거나 떨어진다. 작게 자르면 질문의 단어 여럿이 한 청크에 함께 들어갈 가능성이 줄어든다. 2,400자는 측정하지 않았다.
- 실험 D (내 검색어, Windows 리허설에서 Claude가 `my_rewrites.jsonl` 작성 → `--rewrite-file`): 한국어 질문 하이브리드 **25% → 80%** (키워드 0 → 65%, 벡터 25 → 50%), 질문 임베딩 332토큰. 준비된 "한국어 → 영어 검색어"(70%)보다도 높다. Claude가 정답 판정 문구를 검색어에 넣지 않았다고 스스로 밝혔는지 확인시킬 것 — 정답을 흘리면 실험이 무의미해진다.
- 실험 결론 순위(리허설): **D(질문 다듬기) ≫ C(1:1 유지) ≥ 기준 > A(벡터만 상승) > B(하락)**. 조별 발표에서 "가장 싼 실험(D, 0.0001달러)이 가장 큰 개선"을 끌어낸다.

## 5. 운영 주의

- **지역**: Japan East. 한국 지역은 무료 등급 PostgreSQL이 만들어지지 않는다.
- **할당량**: 무료 계정 Japan East는 `text-embedding-3-small` GlobalStandard **1000K TPM**, OpenAI 계정 1개 (2026-11-14 확인). 템플릿 기본값 1000이 그 한도 전부를 쓴다 → 같은 구독에 두 번째 배포는 InsufficientQuota. 재배포하려면 먼저 리소스 그룹을 지우거나 Capacity를 낮춘다.
- **리소스 공급자**: 새 무료 계정은 공급자가 모두 미등록이다. 템플릿 배포가 PostgreSQL·App·OperationalInsights를 자동 등록했다. 포털 할당량 화면은 CognitiveServices가 등록되기 전에는 비어 보인다(그래서 사전 과제에서 할당량 확인을 뺐다).
- **작업 폴더**: Mac·Windows 모두 **문서(Documents) 안의 `jpm-class`**, 키트는 `문서/jpm-class/jpm_kit/README.md` 위치(사전 과제 2·4, 키트 `README_먼저읽기.txt`와 같다). Windows의 문서 폴더는 OneDrive로 옮겨져 있는 경우가 많다(`C:\Users\<이름>\OneDrive\문서`). 그래도 쓴다. Code 탭 폴더 선택은 탐색기 왼쪽 **문서**로 찾게 한다. "파일을 사용 중"·권한 오류가 나면 작업 표시줄 OneDrive 아이콘 → **동기화 일시 중지**. - **방화벽**: 배포 때 강의실 IP를 넣는다. 집에서 이어서 하려면 포털 → PostgreSQL → 네트워킹 → **현재 클라이언트 IP 추가**.
- **비밀**: `.env`에만. 채팅·스크린샷에 비밀번호·키가 보이면 즉시 키 재발급(포털 → Azure OpenAI → 키 다시 생성), DB 비밀번호 재설정.

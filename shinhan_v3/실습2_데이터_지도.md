# 2일차 A. 공개 거래 데이터 지도

**역할**: 1일차에 이어 JPMorgan 구조화상품 담당자입니다. 1일차에는 **우리가 낸 상품 문서**(424B2)를 읽었습니다. 오늘은 그 상품 가격을 정할 때 기준이 되는 **시장 금리**를, 누구나 받을 수 있는 공개 데이터로 확인합니다.

**목표**: 오늘 쓸 공개 데이터 네 곳을 구분하고, 각각 *누가 내는지 · 무엇이 들어 있는지 · 언제 나오는지 · 무엇이 가려져 있는지*를 말할 수 있게 됩니다. 실습 B~E는 모두 이 지도 위에서 움직입니다.

| 할 일 | 시간 |
|---|---|
| 1. 지도 한 장 보기 (설명) | 5분 |
| 2. 실제 거래 한 건 읽기 (설명 + 같이 읽기) | 5분 |
| 3. Claude에게 네 곳에서 한 건씩 받아 오게 하기 | 7분 |
| 4. 확인 질문 | 3분 |

> 이 실습에는 DB도 Azure도 필요 없습니다. VS Code, Claude Code, `uv`만 씁니다. 받은 것은 `jpm_kit/out/`에 파일로 남깁니다.

## 1. 지도 한 장

**무엇이 들어 있나**

| 출처 | 누가 · 왜 | 무엇이 | 가려진 것 |
|---|---|---|---|
| **① DTCC 스왑 공시** | DTCC(거래정보저장소). 법(CFTC Part 43, SEC Reg SBSR)상 장외 스왑은 **거래 직후 공개**해야 함 | 스왑 **거래 한 건 한 건**: 체결 시각, 시작일·만기일, 원금, 통화, 고정금리, 기초금리 이름, 청산 여부, 거래 플랫폼 (한 건에 항목 110개) | **거래 상대방 이름 없음**. 큰 거래는 원금에 상한(`250,000,000+`). 블록 거래는 늦게 공개 |
| **② NY Fed 기준금리** | 뉴욕 연방준비은행. SOFR 등 기준금리의 **공식 산출 기관** | **하루에 숫자 하나**: SOFR(국채 담보 하루짜리 레포 금리), 거래량, 분포(1·25·75·99 백분위). EFFR·BGCR·TGCR·OBFR도 | 개별 거래 없음 (집계값) |
| **③ 재무부 국채 금리** | 미국 재무부. 국채 시장 가격으로 만든 **공식 수익률 곡선** | **하루에 곡선 하나**: 1개월~30년 14개 만기 | 개별 거래 없음 (모형으로 만든 곡선) |
| **④ TreasuryDirect 경매** | 미국 재무부(발행). 국채 **경매 결과** | **경매 한 번에 한 행**: 낙찰 금리, 응찰 배율, 발행액, 입찰자 유형별 배정 (항목 187개). 예: 11/25 4주 단기채 1,050억 달러, 낙찰 4.115%, 응찰 배율 2.64 | 누가 샀는지 없음 (유형별 집계) |

**1일차 SEC 공시와 비교**

| | 1일차: SEC 424B2 | 오늘: DTCC 스왑 공시 |
|---|---|---|
| 누가 쓰나 | 발행사(JPMorgan)가 직접 | 거래 당사자가 신고 → DTCC가 익명으로 공개 |

| 읽는 법 | 텍스트로 바꾸고 검색·추출 | 표 그대로. 대신 **어떤 행을 걸러낼지**가 핵심 |

## 2. 실제 거래 한 건 읽기 (2026-11-25, DTCC 하루치 파일에서)

### 미국 달러 10년 SOFR 스왑

| 칸 | 값 | 뜻 |
|---|---|---|
| Dissemination Identifier | `6538971218000000101` | 공개 번호. 정정·취소 행은 *Original Dissemination Identifier*로 이 번호를 가리킨다 |

| Cleared | `I` | 청산소에서 청산할 예정 (`Y` 청산됨, `N` 청산 안 함) |
| Platform identifier | `TWSF` | 거래 플랫폼 코드 (Tradeweb SEF). `XOFF` = 플랫폼 밖 |

## 4. 네 곳이 어떻게 이어지나

| 단계 | 출처 | 만기 | 무엇을 말해 주나 |
|---|---|---|---|
| 하루짜리 금리 | ② SOFR | 하루 | 오늘 국채 담보로 하루 빌리는 값 |
| ↓ "앞으로 N년 동안 SOFR를 받는 대신 고정금리를 내겠다" | | | |
| 스왑 금리 | ① SOFR 스왑의 고정금리 | 1~30년 | 앞으로 SOFR가 평균 얼마일지에 대한 시장 가격 |
| ↕ 같은 만기끼리 빼면 **스왑 스프레드** | | | |
| 국채 금리 | ③ 국채 수익률 곡선 | 1개월~30년 | 미국 정부가 N년 빌리는 값 |
| ↑ 새로 발행할 때 | ④ 국채 경매 낙찰 금리 | 발행 만기 | 곡선의 그 만기 근처인가 |

- **②→①**: SOFR 스왑의 고정금리는 "앞으로 SOFR가 평균 얼마일까"에 대한 시장 가격입니다.
- **①↔③**: 같은 만기에서 스왑 금리와 국채 금리의 차이가 **스왑 스프레드**입니다. 구조화상품의 쿠폰과 내재가치를 정할 때 쓰는 할인율이 이 근처에서 나옵니다. (1일차의 "발행가 대비 추정가치 차이"를 떠올려 보세요.)
- **④→③**: 새로 발행된 국채의 경매 금리가 곡선의 해당 만기 근처에 있는지 확인할 수 있습니다.

## 5. Claude에게 네 곳에서 한 건씩 받아 오게 하기

Claude Code 패널:
```
아래 네 곳에서 각각 가장 최근 값 한 건씩만 받아서 표로 보여줘. 짧은 코드는 jpm_kit/out/ 에 파일로 만들어 uv run 으로 실행해.
1. DTCC 최근 금리 스왑 거래: https://pddata.dtcc.com/ppd/api/ticker/CFTC/RATES — 원화(KRW) 거래가 있으면 그것, 없으면 첫 거래.
   체결 시각, 공개 시각, 시작일, 만기일, 원금, 통화, 고정금리, 기초금리 이름만.
2. NY Fed SOFR: https://markets.newyorkfed.org/api/rates/secured/sofr/last/1.json — 날짜, 금리, 거래량.
3. 재무부 국채 수익률 곡선: https://home.treasury.gov/resource-center/data-chart-center/interest-rates/pages/xml?data=daily_treasury_yield_curve&field_tdr_date_value_month=<이번 달 YYYYMM> — 가장 최근 날짜의 1년·2년·5년·10년·30년.
4. TreasuryDirect 최근 경매: https://www.treasurydirect.gov/TA_WS/securities/auctioned?format=json&pagesize=1 — 경매 마감일(competitiveAuctionCloseDate), 종류, 기간, CUSIP, 낙찰 금리(단기채는 highRate·investmentRate, 중장기채는 highYield), 응찰 배율(bidToCoverRatio).
규칙: 각 주소에 한 번씩만 요청하고, 실패하면 다시 시도하지 말고 오류 내용만 보여줘. 받은 원본은 jpm_kit/out/map_<이름>.json 으로 저장해.
HTTP 요청은 urllib 말고 httpx 로 해(스크립트 맨 위 # /// script 에 dependencies 로 적기).
마지막에 "체결/기준 시각"이 서로 얼마나 다른지 한 줄로 정리해줘.
```

## 이용 규칙

- DTCC 주소는 공식 API가 아니라 **공개 대시보드가 쓰는 주소**입니다. 같은 주소를 짧은 간격으로 반복해 부르지 않습니다(최근 거래는 1분에 한 번 이하). 많이 받을 때는 하루치 zip을 씁니다.
- 공개 데이터라도 출처를 밝힙니다: *DTCC Public Price Dissemination, Federal Reserve Bank of New York, U.S. Department of the Treasury.*
- 마지막 줄(httpx)이 없으면 TreasuryDirect에서 `CERTIFICATE_VERIFY_FAILED` 오류가 납니다. 파이썬 기본 `urllib`의 인증서 목록에 이 사이트의 루트 인증서(Sectigo R46)가 없기 때문입니다(2026-11-27 확인).
- 재무부 Fiscal Data API(`api.fiscaldata.treasury.gov`)는 교내 네트워크에서 막힐 수 있어 오늘은 쓰지 않습니다.

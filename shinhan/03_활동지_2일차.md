## 활동 11. [경험 11] Claude Code가 SEC 원문을 직접 받아 오기 (135–160분)

> 같은 강의실의 모든 요청이 하나의 IP로 SEC에 갑니다. **강사가 부르는 조 순서대로, 한 사람이 원문 1건만** 받습니다.

Claude Desktop → **Code** 탭 → 폴더 `jpm-class`. **Claude는 스크립트를 만들고, 실행은 내가 Desktop 터미널에서 합니다.**
(내 연락처를 넣은 환경변수는 터미널에만 있고 Claude는 보지 못합니다. 이메일이 채팅에 남지 않는 이유이기도 합니다.)

**① Claude에게 스크립트 만들기** (네트워크 요청 없음)
```
내 운영체제는 Windows야(Mac이면 Mac으로 바꿔 쓰기). SEC 공시 원문 1건을 받는 스크립트를 만들어
jpm-class 폴더에 저장해줘. Windows면 PowerShell 5.1용 sec_fetch.ps1, Mac이면 curl을 쓰는 sec_fetch.sh.
규칙: URL은 실행할 때 인자로 받는다. 요청 전에 환경변수 SEC_USER_AGENT에 "이름 이메일" 형식의 연락처가
있는지 검사하고, 없으면 네트워크 요청 없이 LOCAL_PREFLIGHT_CONTACT_MISSING을 출력하고 멈춘다.
요청 전 1초 대기, 동시 요청 1개, 403이나 429면 재시도 없이 즉시 멈춘다. 받은 파일의 크기와 SHA-256을
출력하고, 연락처는 화면·로그에 남기지 않는다. 출력 메시지는 영어로 쓴다. 스크립트를 실행하지는 마.
```
이어서: `이 스크립트가 무엇을 하는지 한 줄씩 설명해줘. 네트워크에 요청하는 줄은 어디야?`
→ **내가 읽고 이해한 스크립트만 실행합니다.**

**② 의도된 실패** — Desktop 터미널을 열고 `jpm-class` 폴더에서 연락처 **없이** 실행합니다.
- Windows: `powershell -ExecutionPolicy Bypass -File .\sec_fetch.ps1 <배정 URL>`
- Mac: `sh sec_fetch.sh <배정 URL>`
- `LOCAL_PREFLIGHT_CONTACT_MISSING`이 나오면 성공입니다. SEC에는 아무 요청도 가지 않았습니다.

> 왜 `-ExecutionPolicy Bypass`? Windows는 기본적으로 `.ps1` 파일 실행을 막습니다(실행 정책). 이 옵션은 **이 명령 한 번만** 허용하고 PC 설정은 바꾸지 않습니다. `Set-ExecutionPolicy`로 PC 설정을 바꾸지 마세요. Mac에는 이 장치가 없습니다.

**③ 내 연락처 설정 후 원문 1건 받기** — **강사가 내 조를 부를 때만** 같은 터미널에서:
- Windows: `$env:SEC_USER_AGENT="Shinhan-class 내이름 내이메일"` → ②의 명령을 다시 실행
- Mac: `export SEC_USER_AGENT="Shinhan-class 내이름 내이메일"` → ②의 명령을 다시 실행
- 403이나 429가 나오면 손을 들고 **다시 실행하지 않습니다.**

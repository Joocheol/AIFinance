# 실습: HTML을 텍스트로 바꾸기 — 변환기가 하는 일

**목표**: 받은 공시 원문(HTML)을 텍스트로 바꾸고, 변환기가 **무엇을 바꾸고 무엇을 바꾸지 않는지** 이해합니다.
변환기(`jpm_kit/htmltext.py`)는 강사가 만들어 2026년 1~10월 공시 19,285건으로 검사한 것을 그대로 씁니다. 고치지 않고 **읽고 확인**합니다.

## 1. 왜 텍스트로 바꾸나

다음 단계들(규칙으로 값 뽑기, 상품 표, 검색, AI에게 읽히기)은 모두 **글자**를 다룹니다. HTML에는 글자 말고도 태그, 글꼴, 위치 정보가 섞여 있습니다.

| | HTML | 텍스트 |
|---|---|---|
| 크기 (중앙값) | 일반 HTML 119KB, PDF 변환형 743KB | 50~60KB |
| `Pricing Date: October 16, 2025` | 표의 두 칸에 나뉘어 태그 사이에 흩어짐 | `Pricing Date: \| October 16, 2025` 한 줄 |
| `Linked to` | `Linke<font …>d to </font>` (낱말 가운데 태그) | `Linked to` |

## 2. 공시 HTML은 두 종류입니다

원본이 그렇게 생겼습니다. 공시 대행사가 어떻게 만들었느냐에 따라 갈립니다.

**① 일반 HTML (문서 구조가 있음)** — 처음부터 HTML로 작성. 문단은 `<p>`, 표는 `<table><tr><td>`.
```html
<tr><td>Pricing Date:</td><td>October 16, 2025</td></tr>
```

**② PDF를 HTML로 바꾼 형식** — Word·조판 프로그램으로 PDF를 만든 뒤 변환 도구로 HTML로. 문단·표 태그가 없고, 화면의 **한 줄 = 상자 하나**가 **좌표**로 놓여 있습니다.
```html
<div class="t …" style="left:935.99px; bottom:12842.0px; font-size:379.2px">Uncapped Digital Barrier Notes Linke<font style="letter-spacing:0.364px">d to </font>the Lesser </div>
<div class="t …" style="left:935.99px; bottom:12405.2px; font-size:379.2px">Performing of …</div>
```
브라우저로 열면 PDF와 똑같이 보이지만, "이 글자들이 한 문장"이라는 정보가 파일에 없습니다. 좌표를 보고 다시 맞춰야 합니다.

> 2026년 1~10월 공시 19,285건에서 ②는 5,896건(31%)이었고, 모두 대행사 한 곳(접수번호 앞자리 `0001213900`)에서 나왔습니다.

## 3. 변환기가 하는 일

원칙은 하나입니다. **글자는 하나도 바꾸지 않고, 글자 사이에 무엇을 넣을지만 정한다**(붙임 / 공백 / 줄바꿈 / 칸 구분 ` | `).
태그를 지우는 것만으로는 이 결정을 할 수 없습니다. 태그가 있던 자리에 공백을 넣으면 `Linke d to`가 되고, 아무것도 안 넣으면 `Pricing Date:October 16`이 됩니다.

### ① 일반 HTML (`dom_to_text`)

| 규칙 | 원문 | 결과 |
|---|---|---|
| 문단·목록 같은 덩어리(`<p>`, `<div>`, `<li>` …)는 줄을 바꾼다 | `<p>…notes.</p><p>The notes…</p>` | 두 줄 |
| 표의 한 행은 한 줄, 칸 사이는 ` \| ` | `<tr><td>CUSIP:</td><td>48136HP69</td></tr>` | `CUSIP: \| 48136HP69` |
| 글자 가운데의 태그는 그냥 붙인다 | `Linke<font>d to</font>` | `Linked to` |
| `<br>`(줄바꿈)이 문장·날짜 한가운데면 공백, 아니면 줄바꿈 | `June 29,<br>2028` | `June 29, 2028` |
| HTML 소스 안의 줄바꿈은 화면에서 공백일 뿐 | `the\nnotes` | `the notes` |
| 화면에 안 보이는 것은 뺀다 | `<script>`, `<style>`, `<!-- 주석 -->` | (없음) |
| 폭을 지정한 넓은 빈 상자는 다른 항목 사이의 빈칸 | `Investments —<font style="width:400pt"> </font>PS-1` | `Investments — \| PS-1` |

### ② PDF를 HTML로 바꾼 형식 (`pdf_to_text`)

| 규칙 | 판단 근거 | 결과 예 |
|---|---|---|
| 높이(`bottom`)가 같은 상자들은 한 행 | 좌표 | 표의 한 행 |
| 같은 행에서 멀리 떨어진 상자는 다른 칸 | 간격 > 글자 크기의 1.5배 | `Per note \| $1,000` |
| 상자 안의 빈 간격 조각(`_`)은 폭으로 판단 | 글자 크기의 15% 이하 = 붙임, 그보다 넓으면 공백, 5배 넘으면 칸 | `January , 2026 \| Registration Statement Nos.` |
| 작은 글씨가 살짝 위에 있으면 위첨자 | 글자 크기·높이 | `S&P 500` + `®` → `S&P 500®` |
| 줄 간격이 보통이고 문장이 이어지면 같은 문단 | 줄 간격, 앞 줄이 `,`·`and`·`the` 등으로 끝나거나 다음 줄이 소문자로 시작 | 화면의 세 줄 제목 → 한 줄 |
| 줄 끝 하이픈 + 소문자로 시작하는 다음 줄 | 하이픈 | `under-` + `lying` → `under-lying` (하이픈은 남김) |

### ③ 두 종류 공통

| 규칙 | 결과 |
|---|---|
| 날짜 가운데의 줄바꿈은 공백으로 | `June 29,⏎2028` → `June 29, 2028` |
| 글머리표(●•▪) 바로 뒤에 글자가 붙으면 공백 하나 | `●The notes` → `● The notes` |

### 바꾸지 **않는** 것

- 글자 자체. 철자, 숫자, 기호, 원문에 있는 공백(`5, 210.975`처럼 원문이 이상해도 그대로).
- "숫자 사이 공백 지우기" 같은 정리. 예전 변환(v1)이 이것을 했다가 날짜를 `October 16,2025`로 망가뜨렸습니다.

### 변환이 맞는지 어떻게 아나 (강사 검사)

| 검사 | 기준 | 결과 |
|---|---|---|
| 1. 글자 보존 | HTML 화면 글자와 변환 결과가 공백·`\|`를 빼면 순서까지 같다 | 19,285건 실패 0 |
| 2. 숫자 온전함 | 날짜·금액·비율이 줄바꿈으로 끊기지 않고 원문에 없는 공백이 끼지 않는다 | 19,285건 실패 0 |
| 3. 정답 근거 | 정답 27건의 근거 문구 261개가 한 줄 안에 그대로 있다 | 261/261 |
| 브라우저 대조 | 크롬으로 그린 글자 위치의 간격과 변환 결과의 띄어쓰기를 비교 (표본 29건) | 글머리표·넓은 빈칸 문제를 찾아 고침 |

**알려진 한계**: 기호 글꼴로 그린 글머리표는 원문 글자가 영문자라 `n If the …`처럼 남습니다. 흐름도 안의 칸 몇 곳은 공백으로 이어집니다.

## 4. 내 10월 원문 바꾸기

Claude Code 패널 또는 VS Code 터미널:
```
uv run jpm_kit/to_text.py
```

| 확인 | 내 값 |

| 변환한 공시 수 | |
| 일반 HTML / PDF 변환형 | / |
| 글자 보존 검사 통과 / 실패 | / |

## 5. 두 종류를 하나씩 원문과 나란히

위 출력의 예시 accession을 하나씩 씁니다.
```
uv run jpm_kit/to_text.py --show <accession>
```
같은 공시를 브라우저로 엽니다: `jpm_kit/sec_oct/html/<accession>.html` 더블클릭.

| | 일반 HTML | PDF 변환형 |
|---|---|---|
| accession | | |
| HTML 크기 → 텍스트 크기 | | |
| 화면에서 여러 줄인 제목이 텍스트에서는? | | |
| 가격 표(Price to Public …) 한 행이 텍스트에서는? | | |
| 원문과 다르게 보이는 곳이 있으면 적기 | | |

## 6. Claude에게 변환기 한 부분 설명 듣기

```
jpm_kit/htmltext.py 의 _line_text 함수와 pdf_to_text 함수가 하는 일을 설명해줘.
특히 빈 간격 조각을 붙임/공백/칸으로 나누는 기준이 무엇이고, 그 숫자(0.15, 5.0, 1.5)를 바꾸면
어떤 문제가 생길지 예를 들어줘. 코드는 고치지 마.
```

> 확인: Claude의 설명이 이 실습지 3절의 표와 맞나요? 다르면 코드에서 해당 줄을 찾아 누가 맞는지 확인합니다.
